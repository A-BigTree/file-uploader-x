# 默认输入处理器

把用户交进来的文件"接住"，放到本次上传的专属目录里，并认出它到底是什么类型的文件。

## 能做什么

- 用户给一个本地路径，它把文件复制一份到工作目录，后续操作都在副本上进行，不碰原文件
- 用户给一个网址，它把文件下载下来
- 不管来源是什么，都读一下文件内容认出真实类型（是图片还是 PDF），并算出准确大小

## 为什么需要它

它是整条上传流程的第一站。后面的校验插件要判断"这是不是图片""有多大"，
就得先有人把文件拿到手、把类型和大小填准。这件事就由它来做。

如果关掉它的全部功能，后面的插件将拿不到可靠的类型和大小信息。

## 什么时候用它

基本上每条上传流程都应该放它在最前面。少数例外：

| 场景 | 怎么设 |
|---|---|
| 常规上传（推荐） | 三个开关全开，用默认值即可 |
| 文件很大、不想多存一份 | 关掉「缓存本地文件」 |
| 想自己写下载逻辑（比如要带鉴权头） | 关掉「下载网络文件」 |
| 只想过一遍，不改动任何东西 | 三个开关全关 |

## 怎么配

### 常规用法

什么都不用改，四个参数的默认值就是推荐配置。

### 不想多存一份文件

关掉「缓存本地文件」。

关掉后，本地文件不再复制到工作目录，后续插件直接读用户给的原始路径。
省磁盘，但要注意：上传过程中如果原文件被删除或修改，流程会出错。

### 网络文件想自己下载

关掉「下载网络文件」。

关掉后遇到网址不会去下载，而是把网址原样传给后面的插件，
由你自己的插件决定怎么取（比如需要带 token、需要走代理、需要分片）。

### 不需要识别类型

关掉「嗅探文件类型」。

关掉后不再读取文件内容，类型信息保持上游传进来的原值。
**注意**：这会让后面按类型校验的插件失去判断依据。

### 网络慢，下载老是超时

把「下载超时」调大，比如 `120`（秒）。默认 30 秒。

## 参数一览

| 参数 | 作用 | 默认 | 什么时候改 |
|---|---|---|---|
| 缓存本地文件 | 本地文件是否复制一份到工作目录 | 开 | 文件很大、不想占额外磁盘时关掉 |
| 下载网络文件 | 遇到网址是否自动下载 | 开 | 想自己控制下载过程时关掉 |
| 嗅探文件类型 | 是否读文件内容认出真实类型 | 开 | 几乎不建议关 |
| 下载超时 | 下载一个文件最多等多少秒 | 30 | 网络慢或文件大时调大 |

## 常见问题

**类型认错了 / 显示为空**

它靠读取文件开头的内容来判断类型，对常见格式（图片、视频、音频、PDF、压缩包）识别很准，
但对纯文本、CSV、自定义格式这类没有特征标记的文件可能认不出来，此时类型会是空的。

如果后续要拦掉这类认不出来的文件，可以在「上传文件校验器」里打开严格模式。

**改过后缀名的文件，认出来的是哪个类型？**

真实类型。把 exe 改名成 png，它照样认出这是可执行文件。

**为什么提示工作目录没设置？**

开启了「缓存本地文件」或「下载网络文件」时，必须有一个工作目录用来存放文件。
这个目录由调用方在发起上传时提供，不是在这里配的。
如果确实不需要工作目录，把这两个开关都关掉。

**下载失败了怎么排查**

提示信息里会带上具体网址和原因：

- 提示"下载失败" —— 网络不通、域名解析不了，或者超时了
- 提示带状态码（如 403、404） —— 网址能通但对方拒绝了，多半是需要鉴权或链接已失效

需要带鉴权的场景，请关掉「下载网络文件」自行处理。

**处理完文件放哪了？**

放在本次上传的工作目录里，文件名是系统生成的唯一名字（避免重名冲突），
原来的文件名信息不会丢，仍然会传给后面的插件。

**能一次处理多个文件吗？**

当前一次流程处理一个文件。多文件请分多次上传。
